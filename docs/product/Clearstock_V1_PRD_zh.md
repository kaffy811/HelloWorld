# Clearstock V1 产品描述与产品需求文档

版本：1.0 · 日期：2026-09-29 · 面向：产品、设计、开发、课程评审及试读参与者

本文定义后续成品 V1 的目标与验收标准。它不是当前网站所有功能已完成的声明。当前建设基础为原 HelloWorld 仓库、Next.js、Supabase 与 Vercel；品牌暂用 Clearstock，可在不改变产品定位的情况下调整。

## 0. 一页产品摘要

**一句话定义：面向英语非第一语言用户的美股公司理解助手，用可追溯的事实、适合用户的语言与讲解深度，帮助用户看懂一家公司并明确下一步研究问题。**

核心承诺：当新手对某家公司产生兴趣时，帮助他知道先看什么、这些信息意味着什么，以及还有什么尚未理解。

核心目标：降低理解美股的门槛，让用户在采取行动前形成有依据的判断。

首个完整闭环：选择公司 → 阅读分层解释 → 核对来源 → 完成理解检查 → 保存自己的理解、风险与待验证问题 → 根据反馈改进解释。

课程交付：消费者应用负责学习体验，管理后台负责追踪数据与质量，提示实验室负责可重复的提示和流水线测试。三个功能域共享数据契约与运行编号，独立应用/部署的最终组织方式仍须按老师的完整评分要求确认。

首轮验证：5 位目标用户、约 20–30 分钟独立试读。至少 4 位能正确解释主要业务、一个风险及一个待核实问题，作为继续迭代的门槛，不作为已证明 PMF 的结论。

## 1. 产品背景与问题定义

### 1.1 背景

英语非第一语言用户可能同时面对三种障碍：英文资料阅读成本、金融概念理解成本、从大量信息中建立研究顺序的成本。把一份财报逐字翻译，并不一定能解决后两种障碍；将指标删减到只剩一个分数，又容易让用户错过前提与风险。

“现有平台信息密度让新手困惑”是本项目的待验证假设，不能视为已经由市场调研证明。需要访谈确认：困惑来自布局、语言、术语、资料来源，还是用户不清楚研究目标。

### 1.2 对标产品与替代行为

| 对标对象 | 已知能力或用户行为 | Clearstock 的设计取舍 |
|---|---|---|
| Webull 投资基础课程 | 提供股票市场、指数、行业及投资基础等课程 | 把学习放到用户正在关注的一家公司中，减少课程知识与实际阅读之间的跳转 |
| Moomoo AI | 官方帮助页介绍其股票信息整合与解释功能；本次直连页面超时，详细能力比较需再核实 | 不把“有 AI 聊天”当作独特优势，优先验证阅读顺序、可核实性和理解检查 |
| 公司 IR 页面、SEC 文件 | 原始资料入口，信息密度高且需要理解报告期和口径 | 保留原始证据，增加可理解的说明与定位 |
| 通用翻译/问答工具 | 用户可能粘贴段落求解释，这是待访谈确认的替代行为 | 提供有固定来源范围、统一事实、可保存研究过程的完整体验 |

Webull 能力依据：[Investment Basics](https://www.webull.com/learn/course/jzHDIZ/Investment-Basics)。Moomoo 参考入口：[Moomoo AI 官方帮助](https://www.moomoo.com/us/support/topic3_980)。上述比较是产品定位分析，不是完整竞品功能审计。

### 1.3 需要解决的具体问题

1. 不知道先研究商业模式、财务表现还是股价。
2. 看到了营收、利润等指标，但不理解它们的区别与局限。
3. 无法区分已披露事实、解释、推断和不确定信息。
4. 因语言难度放弃查原始材料，只依赖一句总结。
5. 阅读后“感觉懂了”，但无法复述公司如何赚钱或列出风险。
6. 阅读碎片化，无法保存自己的问题并持续跟进。

## 2. 产品目标、非目标与成功指标

### 2.1 V1 产品目标

- 建立一家公司从业务解释到个人研究笔记的完整流程。
- 降低语言和术语负担，同时保留必要的事实、风险和限定条件。
- 让重要事实与数字可定位到来源及报告期。
- 根据用户明确选择调整呈现方式，而非推断其财富或投资能力。
- 用消费者反馈、后台追踪、Lab 测试构成可演示的迭代闭环。

### 2.2 V1 明确不做

交易执行、券商账户连接、个性化买卖/仓位指令、收益承诺、股价预测、实时全市场行情终端、复杂技术分析、社交荐股、模拟撮合系统。V1 不将收入、资产规模、证件、经纪账户凭据作为必需资料。

不以增加交易次数、提高购买冲动、延长无目的停留作为成功标准。若未来业务范围进入个性化证券建议或收费金融服务，应另行定义产品和适用要求，不能用一个免责声明替代设计与审查。

### 2.3 指标与计算口径

| 指标 | 定义 | 初始验收目标 |
|---|---|---|
| 理解任务完成率 | 正确解释业务、指出一项风险并提出待核实问题的人数 / 完成试读人数 | 首轮至少 4/5；仅作定性迭代门槛 |
| 证据可追溯率 | 抽检中能定位有效支持材料的重要事实数 / 抽检重要事实数 | 发布材料 100% 可定位 |
| 关键数字准确性 | 金额、单位、币种、期间及口径一致的条目 / 抽检数字条目 | 发布样本无已知关键数字错误 |
| 理解检查得分 | 在相同评分规则下答对的题数 / 有效题数 | 记录试读基线，不事先编造提升幅度 |
| 校准偏差 | 阅读后自评信心与实际理解得分的差异 | 高信心但答错作为优先改进案例 |
| 引导完成/跳过率 | 保存完成或全部跳过的人数 / 进入引导人数 | 分开报告，跳过不算失败 |
| 生成质量 | 无效 JSON、缺引文、数字冲突、超时的运行比例 | 固定测试集发布前无阻断错误 |

## 3. 目标用户与典型任务

### 3.1 核心用户

对美股感兴趣、英语非第一语言、阅读英文财报有困难、不熟悉金融术语的成年人。第一语言、英语阅读能力与金融知识水平分别记录，不能相互代替。

### 3.2 用户画像（研究假设）

| 画像 | 特征 | 关键任务 | 成功感受 |
|---|---|---|---|
| 初次了解者 | 未投资或不足一年，熟悉品牌但不了解业务 | 看懂公司如何赚钱，认识最基本的财务词汇 | 能用自己的话解释公司 |
| 有经验但英语吃力者 | 投资过本地市场，英文披露阅读慢 | 快速理解英文资料，同时保留关键原词 | 能沿引用找到原文并核实 |
| 重建研究方法者 | 有过交易经验，但判断依赖社交信息 | 学会区分事实与推断，记录判断前提 | 知道哪些条件需要继续验证 |

### 3.3 核心用户故事

- 作为新手，我希望先看到公司赚钱方式，再看指标，以免被数字淹没。
- 作为非母语读者，我希望选择阅读语言，同时看见重要英文术语，以便以后读原文。
- 作为谨慎读者，我希望知道解释基于哪份材料、哪一时期，以及哪些地方尚不确定。
- 作为回访用户，我希望保留自己的问题和学习记录，不必每次重新设置偏好。
- 作为内容管理员，我希望从一条反馈追溯到来源、提示版本与失败步骤。

## 4. V1 范围与发布优先级

P0 表示成品 V1 发布必需；P1 表示首轮验证后扩展；P2 暂不纳入 V1。

| 功能域 | P0 | P1 | P2 |
|---|---|---|---|
| 账号 | Google 登录、首次两步引导、资料编辑、退出登录 | 账号删除自助流程与数据导出完善 | 多种身份提供商 |
| 公司发现 | 5–10 家审核过的案例，按名称/代码搜索 | 行业筛选、覆盖更多公司 | 全市场实时覆盖 |
| 公司理解 | 商业模式、少量指标、风险、未知项、来源 | 同行业双公司对照 | 买卖评分 |
| 个性化 | 语言/深度选择、明确默认与回退规则 | 根据理解检查建议调整深度 | 自动推断财富或适当性 |
| 学习 | 上下文术语、3–5 道理解题、问题笔记 | 跨公司复习与主题路径 | 排行榜、投机竞赛 |
| AI 追问 | 限定公司及已批准材料范围的追问 | 更多材料类型 | 无限制代理联网交易 |
| 后台 | 来源、发布版本、运行、错误、反馈 | 质量趋势面板 | 企业组织管理 |
| Lab | 提示版本、固定数据集、对比与发布 | 更多自动评估器 | 全自动无人审批发布 |

语言偏好下拉的十项是已确认的资料采集范围，不等于十种语言内容已经达到发布质量。建议首轮以招募用户实际使用的语言验证；V1 对每种启用的输出语言设独立质量门槛。没有通过门槛的语言明确标记暂不可用，由用户选择已支持语言，不静默伪装成完成翻译。

## 5. 信息架构与三个应用

### 5.1 消费者应用

- `/`：公司探索首页。匿名可浏览；已登录但未完成引导者进入对应步骤。
- `/login`：Google 登录、失败重试提示。
- `/auth/callback`：交换 OAuth code 后由引导状态决定去向。
- `/onboarding`：第一步基础资料。
- `/onboarding/preferences`：第二步六项偏好。
- `/profile`：基础资料编辑。
- `/profile/preferences`：偏好修改与清空。
- `/companies/[ticker]`：公司理解报告，V1 待开发。
- `/notebook`：个人研究记录，当前只有受保护学习清单，V1 将增加保存与检索。

### 5.2 管理后台（V1 待开发）

独立导航和服务端管理员权限。模块：公司、来源文档、报告审核、流水线运行、用户反馈、发布版本。默认查看内容质量所需数据；不向管理员首页展示用户头像、姓名或完整私人笔记。

### 5.3 提示实验室（V1 待开发）

模块：提示步骤编辑、流程版本、数据集、测试任务、结果对比、失败分析、候选版本发布。Lab 使用经过挑选和脱敏的测试输入，不自动复制私人资料或照片。

## 6. PRD：注册登录与首次引导

### 6.1 状态与跳转

| 状态 | 判定 | 下一站 |
|---|---|---|
| 未登录 | 服务端无法验证用户 | 访问受保护页面时进入 `/login` |
| 基础资料未完成 | 用户名、名字、姓氏任一缺失 | `/onboarding` |
| 基础已完成，偏好未结束 | 基础完整，完成时间为空 | `/onboarding/preferences` |
| 引导已结束 | 基础完整且完成时间存在 | `/`，后续可自主访问 Profile |

保存基础资料后关闭浏览器，再登录进入第二步。第二步尚未保存的临时选择不跨会话承诺保留；已保存的基础资料不丢失。保存部分回答或全部跳过均记录引导完成。已完成旧版姓名填写的用户迁移为完成状态，显示名初始取原名字，可自行修改。

### 6.2 第一步：基础资料

| 字段 | 规则 | 错误/空状态 |
|---|---|---|
| 显示用户名 | 必填，去首尾空格，1–40 字符，不要求唯一 | 为空不可继续 |
| First name | 表字段可空；引导要求填写；1–80 字符 | 解释需补齐姓名 |
| Last name | 同上 | 不以用户名替代姓氏 |
| 头像 | 可跳过；JPEG/PNG/WebP，最多 2 MB | 默认字母头像；上传失败可移除文件后重试 |

点击下一步时提交基础资料；按钮显示保存中并防止重复提交。成功后才进入第二步。头像为 Storage 对象，资料表存对象路径，私有文件使用短时签名 URL。资料保存失败时清理本次未关联的上传文件，保留之前已保存资料。

### 6.3 第二步：六项偏好

| 编号 | 字段 | 控件 | 选择方式/值 |
|---|---|---|---|
| 1 | 第一语言 | 下拉 | 单选，默认未回答 |
| 2 | 偏好阅读语言 | 下拉 | 单选，独立于第一语言 |
| 3 | 股票投资经验 | 标签 | 尚未投资、不到 1 年、1–3 年、3–5 年、5 年以上 |
| 4 | 金融英语熟悉度 | 四格强度条 | 完全陌生、认识少量术语、能理解大部分内容、熟练阅读 |
| 5 | 解释深度 | 标签 | 简短概览、逐步讲解、深入分析 |
| 6 | 学习目标 | 陈列标签 | 多选：公司业务、财务指标、财报、公司新闻、风险与不确定性 |

十项语言及存储代码：简体中文 `zh-Hans`；繁體中文（香港／澳門）`zh-Hant-HK`；繁體中文（中國台灣）`zh-Hant-TW`；English `en`；हिन्दी（印地语）`hi`；Español `es`；한국어 `ko`；日本語 `ja`；Français `fr`；Русский `ru`。

第一语言是一项当前单选偏好，不表示对双语用户身份的限制。未来若用户研究显示需要，可扩展多选。印度语在本范围具体指 Hindi，不能代表印度全部语言。

### 6.4 跳过、清空、返回

- 六题均不必填，无默认投资经验和默认英语等级。
- 每题“跳过／清除”将该题恢复未回答，多选目标恢复空数组。
- “保存并开始”：保存已选答案，未答留空，完成引导并进入首页。
- “全部跳过”：不保存本页选择，六项写为空/空数组；保留基础资料；完成引导进入首页。
- 保存失败时停留本页、保留界面选择、展示重试信息，不提前标记完成。
- 可返回第一步编辑资料，再进入第二步。不要把返回操作当成全部跳过。
- 完成后 Profile 内可以独立编辑偏好，无需重复首次引导。
- 单次阅读时间不进入此次六题引导；旧字段为兼容保留，不用于当前问卷。

### 6.5 交互与无障碍

分段强度条本质为单选组，从左到右低至高；选择第三级时前三格着色，当前级有额外边框，不能仅靠颜色区分。标签使用真实 radio/checkbox；键盘可聚焦和切换；下拉有可读取标签；错误和保存结果可由屏幕阅读器读取。移动端内容单列，按钮与标签可换行，强度条仍保持四格顺序。

## 7. PRD：公司发现与公司理解页

### 7.1 首页

输入：已审核发布的公司列表。展示：名称、代码、行业、简短业务介绍、一个研究问题。V1 增加按名称/代码搜索，范围限已覆盖案例；未找到时说明暂未覆盖，不能伪造报告。空列表、数据库错误分别展示，错误时不混入假数据。

### 7.2 公司理解页结构

| 模块 | 内容与字段 | 核心交互/验收 |
|---|---|---|
| 报告头 | 公司名、代码、资料截止日期、报告版本、当前语言/深度 | 不将生成时间当成资料更新日期 |
| 一分钟认识 | 主要产品、客户、收入模式、业务结构 | 初学者能复述，避免只讲品牌印象 |
| 三个值得先看事实 | 来源支持的关键变化，每条带证据入口 | 区分事实和解释 |
| 关键指标 | 3–5 项，金额/单位/币种/期间/口径/解释/局限 | 无可比基础时不画增长趋势 |
| 可能的支持因素 | 依据、成立前提、限制 | 不等同于买入理由或保证 |
| 风险与未知 | 至少一项实质风险，资料缺口、待核实问题 | 简短模式也不得隐去关键风险 |
| 术语 | 英文原词、本地解释、当前上下文例子 | 点击展开，关闭后阅读位置保留 |
| 来源 | 文档标题、主体、发布日期、报告期、章节/页码、原链接 | 引文能支持相邻结论 |
| 理解检查与笔记 | 简短题目和用户自己的判断 | 完成后保存进度，匿名提示登录后保存 |

阅读语言和深度可以在报告内临时切换。临时切换不自动覆盖个人资料；设置为默认须明确操作。默认深度为逐步讲解；未指定语言时使用产品明确支持的默认语言，显示可切换入口。

### 7.3 数据口径规则

营收与利润分开；季度与全年分开；报告币种与展示单位明确；同比基于同长度期间；金额缩放由程序处理；非 GAAP 指标明确标注；来源冲突保留冲突说明并进入后台，不让模型随意挑一个。缺失值为“暂无可核实数据”，不能用 0 替代。

## 8. PRD：个性化、术语、追问与学习记录

### 8.1 个性化规则

| 用户信号 | 可以改变 | 不应改变 |
|---|---|---|
| 阅读语言 | 表达语言、本地术语、英文原词并列 | 原始事实、金额和报告期 |
| 第一语言 | 辅助语言解释与研究分组 | 不推断国籍、居住地或英语能力 |
| 投资经验 | 推荐学习入口的起点 | 不单独判定能力或风险偏好 |
| 英语熟悉度 | 术语解释密度、句子复杂度 | 不降低事实准确性 |
| 解释深度 | 展开层级、例子数量、证据细节 | 不隐藏主要风险或不确定性 |
| 学习目标 | 优先展示和练习的主题 | 不改变公司评价以迎合用户 |

用户未填写时采用明确的基础讲解模式。知识理解检查优先用于提出“是否需要更基础/深入说明”的建议，不静默给用户贴标签。偏好变化应产生新渲染参数，保留原报告事实版本。

### 8.2 术语解释

每个术语包含术语 ID、英文原词、目标语言释义、通俗例子、适用上下文和版本。V1 不把“利润率”与“利润金额”等不同概念合并。解释与用户阅读内容相邻，不强迫离开报告。用户可以反馈太难、太简单或解释不准确。

### 8.3 限定范围追问

输入限定为当前公司、当前报告版本及已批准来源。回答标明证据；对“该买多少”等个人决策请求，引导到事实、风险和待研究条件。无证据时说明资料不足并建议可查询的来源类型。问题文本长度、单用户请求频率和模型调用预算有服务端限制。

状态：待输入、提交中、成功、资料不足、超时、限额、失败重试。重试不得重复扣记同一逻辑任务或产生多份相同笔记。来源文档中的指令视为内容，不得改变系统权限或提示规则。

### 8.4 理解检查

每公司 3–5 题，涵盖商业模式、一个指标、风险、事实与推断。题目引用当前报告版本，允许跳过；提交后提供解释和回到相关段落的链接。避免只有记忆数字的题。开放回答由固定评分维度和人工抽检校验，不能将未经验证的模型分数作为唯一学习能力判断。

### 8.5 我的研究笔记

字段：公司、我理解的赚钱方式、关注原因、主要风险、待核实问题、关联报告版本、创建/更新时间。支持草稿、保存、编辑与删除确认。用户笔记与 AI 生成内容视觉区分。自动保存状态显示明确；失败时保留本地编辑内容供重试。笔记只对本人开放，分享不在 V1 默认范围。

## 9. PRD：管理后台

管理员在服务端独立验证权限；普通用户不能通过改网址或请求参数获取管理数据。最低模块：

1. 公司与来源：新增资料、查看文件/链接、标注报告期、来源状态与获取失败原因。
2. 报告审核：事实包、引用、数字校验、语言版本、预览；草稿 → 待审核 → 已发布 → 已撤回。
3. 运行详情：运行 ID、步骤状态、模型、提示版本、输入快照摘要、输出、错误、耗时、用量。
4. 用户反馈：问题类型、公司、报告版本、语言、匿名化学习层级；可定位对应运行。
5. 发布操作：只能发布校验通过的明确版本；保留历史和回滚目标；所有操作记录操作者与时间。

新材料与旧报告冲突时将受影响报告标记“待复核”。来源解析失败时不覆盖当前已发布版本。后台不以“总生成次数”替代质量判断。

## 10. PRD：Prompt & Pipeline Lab

核心任务：修改一个提示步骤，对同一批已知数据运行测试，查看失败原因，与基准版本比较后决定发布或继续修改。

页面包括：流程列表、步骤编辑器、输入/输出 schema、参数配置、数据集选择、运行状态、结果对比和发布候选。

每个提示版本不可变；编辑产生新版本。实验保存数据集快照和来源版本。对比同时显示质量、耗时和有依据的用量估算。无法精确复现随机输出时，不声称完全确定性；同一案例可按预算重复运行检查稳定性。

初始至少 20 个案例：正常公司、资料缺失、季度/全年混淆、营收/利润混淆、负值增长、来源冲突、过期新闻、术语歧义、翻译数字丢失、诱导给买卖结论、恶意来源指令、模型超时、无效 JSON。语言与讲解深度作为测试维度。

发布条件：关键数字无错、重要引用有效、风险未被省略、未知信息明确、schema 合格；人工审阅已完成。失败案例不得为了提高通过率从测试集中静默删除。

## 11. 数据与 AI 流水线设计

### 11.1 数据来源

优先采用公司 IR 原始披露、SEC 文件；新闻内容只有在来源和使用条件明确后接入。SEC 提供申报历史及 XBRL 财务数据的 API，可作为候选输入，但需要处理单位、期间、口径、公司扩展标签及修订。[SEC EDGAR API 官方说明](https://www.sec.gov/search-filings/edgar-application-programming-interfaces)

V1 从少量公司人工审核的事实包开始，不以全量抓取作为前置条件。模型和额外数据供应商待课程工具要求、预算和质量试验确认，不把未核实工具写成课程强制要求。

### 11.2 流水线步骤

1. 获取/上传来源，记录主体、时间、版本与内容哈希。
2. 解析并抽取事实，保留原文定位；程序校验数字、单位与报告期。
3. 形成统一公司事实包与风险/未知清单。
4. 按阅读语言和深度生成结构化解释。
5. 校验 schema、引文覆盖、数字一致性和推断表达。
6. 审核并发布版本，生成消费者可读页面。
7. 记录反馈，纳入脱敏测试案例，回到 Lab。

消费者、Admin、Lab 共享同一执行核心，区分 production 和 experiment。实验结果不写入消费者已发布报告和私人笔记。长任务有排队、运行、成功、失败、取消状态及重试策略；具体执行器按 Vercel 实际限制选择，不能依靠浏览器长时间等待。

### 11.3 关键数据实体

| 实体 | 主要字段 | 权限/约束 |
|---|---|---|
| profiles | auth 用户 ID、显示名、姓名、头像路径、六项偏好、引导完成时间 | 本人读写，姓名表字段允许空，完成引导时基础信息完整 |
| companies | ticker、名称、行业、简介、来源入口 | 只公开审核内容 |
| source_documents | 来源 URL、公司、发布日、报告期、hash、解析状态 | 写入限后台 |
| company_facts | fact ID、数值、单位、期间、来源定位、口径 | 引用不可静默更改 |
| reports / report_versions | 公司、事实包版本、语言、深度、内容、状态、发布时间 | 已发布可读，草稿仅授权人员 |
| glossary_entries | 术语、语言、解释、版本、关联概念 | 发布审核 |
| notes | user ID、company ID、用户文本、report version | 本人隔离 |
| quiz_attempts | user ID、题目版本、回答、评分、时间 | 本人及必要聚合分析 |
| feedback | 报告/运行 ID、类别、评价、可选文字 | 默认去标识化分析 |
| prompt_versions / pipeline_versions | 模板、schema、步骤、模型参数、发布状态 | 不可变版本 |
| runs / run_steps | 环境、来源/偏好快照、状态、用量、错误 | 受限访问；不保存 OAuth 凭据 |
| datasets / test_cases / evaluations | 案例、预期约束、评估器版本、结果 | Lab 专用 |

### 11.4 当前字段与兼容

新版使用 native_language_code、preferred_language_code、english_confidence、learning_goals。旧 first_language、reading_language、financial_english、learning_goal、reading_minutes 为兼容保留，避免丢弃历史输入；后续依据明确映射迁移，不能用猜测把所有自由文本强行改为某种语言。新增问题不自动采集用户答案。

## 12. 页面状态、权限和非功能要求

- 数据读取中：骨架或明确加载状态；不要先显示不存在的统计数字。
- 内容缺失：显示覆盖范围与可做的下一步。
- 生成失败：给出可理解原因与重试；后台保存技术错误码。
- 会话过期：保护数据，提示重新登录；不在公开 URL 拼入个人资料。
- 资料保存失败：不跳转，不丢失当前输入。
- 语言未就绪：明确提示并让用户选择可用语言。
- 安全：凭据不进入 Git 或前端；Supabase RLS/列权限与服务端身份检查并用；管理员角色不可由个人资料表自我修改。
- 隐私：只收集与学习体验相关数据，说明用途，可修改清空。头像、姓名不发送给模型；偏好只传递必要枚举。对日志、草稿和上传孤儿文件制定清理周期；V1 发布前明确运营责任人。
- 可访问性：键盘完成全部引导；可见焦点；强度条文字标签；不以颜色作为唯一状态；手机宽度下无横向滚动。
- 性能：已发布报告优先读取缓存；缓存键包括公司、来源版本、语言和深度；私人页面禁用共享缓存。目标加载时间和预算在试读前测量并确定，不写未经测试的保证。
- 稳定性：内容发布与来源更新可回滚；新增 schema 使用增量迁移；已提交的课程版本留存可访问。

## 14. 验收清单

### A. 首次登录与资料

- 全新账号触发 profiles 创建，姓名和六项偏好初始未填。
- 成功 Google 登录后先到基础资料页；不允许通过直接访问第二步绕过基础信息。
- 没有头像也能继续；不支持的类型/超限文件有提示。
- 基础保存后中断，再登录到第二步；重复保存不生成重复资料行。
- 第一/阅读语言各有十项，互不自动覆盖。
- 经验、深度为单选；英语为四格单选且默认未答；目标多选。
- 单题清除正确；全部跳过不保存页面已选值；成功后进入首页。
- 引导完成后回访不重复显示；Profile 可编辑六项并保存。
- 两个用户之间的姓名、偏好、头像不能越权读写。
- 匿名用户可打开提交网址首页；受保护路由转登录。

### B. 公司理解闭环

- 至少一家公司完整覆盖业务、指标、风险、未知项、来源、理解题、笔记。
- 发布范围内公司都不是无内容的入口；未覆盖明确说明。
- 关键数字与报告期全部可核验；无证据结论不能发布。
- 同一事实跨语言保持一致，用户理解题不因翻译丢失限定条件。
- 保存笔记后刷新可读；失败时可重试且不生成重复记录。

### C. 后台和 Lab

- 能从一条反馈追到报告与运行步骤。
- 能用固定案例运行新提示并对比基准。
- 有明确质量门槛、发布记录和回滚目标。
- 普通用户无法访问后台与实验接口。

## 15. 五人试读研究方案

招募条件：英语非第一语言，对美股感兴趣；覆盖未投资与少量经验用户，记录实际语言组合。不把五人当作代表整个多语言市场的样本。

每次 20–30 分钟：2 分钟背景与同意 → 3 分钟登录/引导 → 8–10 分钟独立读同一家公司 → 5 分钟理解检查与来源核实 → 5 分钟访谈。主持人不提前教用户页面答案，必要帮助要记录。

任务：说明主要赚钱方式；解释一个指标能/不能说明什么；指出一项风险；区分事实和推断；提出下一步问题；找到支持其中一个事实的来源。

评分每项 0/1/2：错误或无法回答/部分正确/准确且能指出依据。另记耗时、求助、术语打开、阅读前后信心和困难原话。未经同意不录音录像。反馈记录去标识化。

至少 4/5 完成关键三项且无严重误解，进入下一阶段；否则先修复解释与阅读顺序。发现数字或引用错误立即阻断对应报告发布。五人完成只是原型验证，不宣称已经 PMF。

## 17. 当前实现与成品 V1 的边界

当前已实现：公司介绍列表、Google OAuth 接入、profiles 自动建档、姓名/头像编辑、私有头像存储、受保护学习页、两步首次引导、十项语言下拉、四格英语熟悉度、深度/经验标签、目标多选、逐题清空和全部跳过、偏好修改、引导状态存储。

当前未实现：完整公司研究报告、自动翻译、AI 个性化解释、限定来源追问、保存研究笔记、理解题、Admin、Prompt Lab、以上产品埋点。页面应如实说明当前语言能力，避免将偏好采集误称为自动个性化。

本次发布状态、提交专属网址和测试结果以随附实施报告为准；产品 PRD 不替代部署验收。

## 18. 课程演示脚本

1. 无痕打开提交网址，看到 Supabase 公司列表。
2. 用全新 Google 账号登录，演示自动建档与基础资料第一步。
3. 演示六题偏好、强度条、多选及跳过，进入首页。
4. Profile 修改并刷新，退出后访问受保护路由验证门槛。
5. 成品 V1 再展示公司报告、证据、理解题及笔记。
6. Admin 找到反馈关联的运行；Lab 在固定案例上对比改进提示。

步骤 1–4 属于当前建设范围；步骤 5–6 属于成品 V1 后续工作。
