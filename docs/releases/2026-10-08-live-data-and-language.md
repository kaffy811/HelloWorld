# 美股行情、AI 资料与系统语言更新（2026-10-08）

这版解决三个问题：列表行情不刷新、旧 AI 分析误被理解成当前没有行情、每个 AI 工具重复选择语言。

## 实际行为与数据边界

- 现有六只股票和 SPY / QQQ / DIA 在可见页面中每 15 秒检查一次。数据来自 Alpaca IEX 的真实快照，后台通过 Supabase 的共享租约合并访客请求。前端暂停后台标签的请求，失败时保留最近报价并显示状态。
- 这是每 15 秒刷新的近实时页面，不是逐笔推送；只有 IEX 单一交易所的价格与成交量。ETF 价格不是标普、纳斯达克、道指的指数点位。官方市场时钟显示常规交易时段状态；盘后可能仍有少量更新，休市时不能保证报价变化。
- 报价附最近成交时间；检查时间与成交时间不同。成交量附 dailyBar 的时间，不当作全市场成交量。图表日内数据每 60 秒更新、常规交易时段内展示，日线历史及技术特征通过手动数据同步更新，不能当成逐笔指标。
- 新闻显示“当前可用资料”，同时保留旧分析的原始生成上下文和评分。新解释加入当前报价、涨跌、成交量，以及已完成日线的历史截止时间、20 日均价和 5 / 20 日收益特征；不能据此认定公告导致了价格变化。
- SEC 原文按官方 URL 缓存，保存完整标准化文本、SHA256 与获取时间。成本控制采用确定性的相关段落检索，保存实际入模的段落和字符位置。缓存完整文件不等于模型逐行阅读了完整报告。准备失败时明确回退至片段。已验证 Costco 10-K 原文 210,654 字符。
- 初次点击“解释文章”会先准备 SEC 原文，然后发起独立 AI 请求，避免原文下载和模型生成占用同一个请求的全部时间预算。

## 一处设置语言

在 `/settings` 选择 English / 简体中文。已登录用户保存到自身 `profiles.preferred_language_code`；浏览器也保存 HttpOnly 语言 Cookie，支持匿名访问。界面通过 React 文本与翻译目录渲染，服务端强制 AI 使用系统语言，不接受组件自行覆盖。学习偏好页不再修改系统语言。

新闻原始英文资料、公司名称、代码、文档原始生成记录保留来源语言。旧 AI 回答和评分保留版本；新聊天按文档校验值与真实报价证据创建版本；报价或历史特征变化后重新点击解释，会形成新的资料版本，自动刷新不会自动消耗 AI 额度。另一种语言的旧分析折叠展示，点击“解释文章”或“翻译文章”生成对应系统语言的新版本。旧聊天在另一语言继续追问时创建新的语言版本，原记录不覆盖。每日学习按用户 / 纽约日期 / 语言缓存；切换语言可能使用另一次生成额度，仍受全站每日限额限制。

提示词版本为 `us-reader-v9`，新公告分析为 `us-learning-v5`。生成记录保存真实输入、来源、语言、模型、配置、输出与 usage，支持已有下载 / replay 工具。数值显示精度由后端处理，模型无需自行计算。新增毛利与毛利率区别的校验。

## 扩展到更多美股

| 阶段 | 推荐做法 | 成本与边界 |
| --- | --- | --- |
| 6 → 20 只 | 在 companies 增加 ticker、market=US、名称、行业、简介、SEC CIK。运行 `npm run sync:data` 补日线/财务/公告。列表、Watchlist、报价批次、图表许可名单使用数据库公司目录。 | 9 个当前标的含 ETF 一批请求，约每分钟 4 次快照请求，另加最多一次市场时钟请求。所有访客共享，不按人数增加数据商请求。 |
| 20 → 约 30 个活跃标的 | 在有常驻进程的环境建立一个 IEX WebSocket 收集器，订阅当前活跃标的，向浏览器转发。 | Basic 官方上限为 30 个流式订阅标的。Vercel 请求函数不能作为永久 WebSocket 收集器；免费常驻主机的休眠、配额和可用性需另行评估。 |
| 30 → 100 个目录标的 | 保留 REST 批量快照；按活跃页面与自选股安排优先级，50 个一批。无用户访问时停止高频收集。 | 当前实现总目录上限 100（包含三个 ETF），超出时明确报错，避免静默漏标的；进入下一阶段前需扩大租约时长、处理分页及任务分片。 |
| 更大范围 / 全市场逐笔 | 拆分市场收集器与财务/新闻任务，增加分页和队列；评估付费 SIP 数据与展示/分发授权。 | 不能把免费 IEX 宣称为完整实时美股。数据 API 套餐并不自动证明网站有公开商用分发权。 |

Alpaca 官方 Basic 当前为免费 IEX 实时股票数据、30 个流式订阅标的及每分钟 200 次历史 API 请求；套餐和权限可变化，以上请求量是当前实现的预算，不是服务可用性的保证。[官方套餐说明](https://docs.alpaca.markets/us/docs/about-market-data-api)、[IEX 与 SIP 区别](https://docs.alpaca.markets/us/docs/market-data-faq)、[实时流文档](https://docs.alpaca.markets/us/docs/real-time-stock-pricing-data)。网站公开商用前另行确认数据商与交易所的展示/分发条款：[Alpaca agreements](https://alpaca.markets/disclosures)、[IEX market data agreements](https://www.iex.io/resources/trading/market-data)。

新股票的新闻行业标签仍需在资料同步分类器中配置对应行业，不应把未知行业归成消费行业。当前工程对新增股票的价格、详情页和 Watchlist 已使用动态目录；市场完整分类体系是下一步扩展验收项。

## 复现与验收

1. 现有环境密钥即可运行，不需要新密钥。生产已应用 `202610080005_live_context_language.sql`；不要重复执行迁移。23 张应用表全部启用 RLS，缓存表仅服务端可读写。
2. 本地运行 `npm run check:setup`、`npm run lint`、`npm test`、`npm run test:db`、`npm run build`。数据库测试在隔离 PGlite 中运行。
3. 本地服务运行在 `http://127.0.0.1:3100`。登录后进入设置选择语言，再进入 COST 公告，准备 SEC 原文、解释文章、展开五级评分并保存聊天。Notebook 可重新打开历史记录。
4. 新 UI 会显示 IEX 范围、官方市场状态、成交时间和原文缓存状态；生成记录可核对新版本提示词与 `market-snapshot` 来源。
5. 本次改动尚未发布到 Vercel。部署前需要将同一代码和迁移状态对齐，并核对公开展示的数据权限；没有修改订阅、计费或部署保护。
